流程要点： ① 首次使用必须保存 企业ID 与 账号ID，作为后续所有调用的身份标识； ② 人员信息报送成功后，方可进入算税与申报； ③ 申报成功后先判断有无税款，只有税款 > 1 元才需要发起缴款； ④ 申报更正需重新走“申报数据报送”链路，申报作废不可恢复，需谨慎。
异步交互范式
所有写入类接口遵循 Save → pclsh → 轮询 的三段式异步范式
1
提交 Save
企业系统组装报文，带 nsrsbh/djxh/业务数据，调乐企 Save 接口
2
受理返 pclsh
乐企受理通过后返回 pclsh（批次流水号），标记 returncode=10（处理中）
3
异步转征管
乐企异步将报文转发至税局征管核心，税局落地登记/校验/入库
4
轮询查结果
企业轮询查询接口（带 pclsh），returncode=00 成功，取回税局生成数据
同步 vs 异步： 查询类接口（列表查询、信息查询、统计）为同步直接返回； 写入类接口（报送、申报、作废、更正、缴款）为异步需轮询。 更正/作废操作必须携带原 sbuuid 或对应UUID定位原记录。
# 异步交互伪代码 step1 resp = POST("/save", payload={nsrsbh, djxh, ...业务数据}) # → 返回 pclsh, returncode=10 step2 while returncode == "10": result = POST("/query", {pclsh}) # → returncode=00 成功 / =20 失败 sleep(3s) step3 if returncode == "00": # 取回税局生成的 sbuuid / 人员UUID / 算税结果 等 return result.data

常见问题 FAQ
来源：企享云个税申报实际业务问题（共33题）
FAQ 来源：企享云 API 文档 个税申报-常见问题。 以下问题均为实际业务对接中遇到的典型场景与报错，按业务模块分类整理。

一、企业初始化 / 账号管理

Q1. 用户确认密码正确，但账密校验请求仍返回密码错误
答：在确认密码正确的情况下，查看选择的登记税务机关是否正确。不同的登记机关，申报密码会有不同的情况。
Q2. 多税局企业，首次选择了 A 税局，后面还能修改所属税局吗
答：可以通过「账号信息上传并校验（申报密码校验）」接口传入新的主管税局，会返回新的 accountId 账号 ID。
Q4. 账号信息校验的实名账号和密码是怎么获取的
答：这个是被授权办税人的个人所得税的账号和密码（自然人电子税务局账号）。
Q6. 局端接口返回异常: 授权关系校验不通过
答：登录方式为实名账号登录，但企业并没有授权办税人权限。需要调整为账号密码登录（企业税办税员 ≠ 个税办税员）。
Q9. 请求参数非法: djzclxDm 不能为空
答：一般是企业的主管机关问题，需要客户联系专管员处理。
Q11. 受理税务机关代码不能为空或空白字符串
答：一般是企业的主管机关有问题，需要客户联系专管员处理。
Q12. 申报失败，扣缴单位无有效的税费种认定信息
答：两种可能：1. 通过企业注册接口查询是否存在多个主管机关，账号密码上传接口传的登记序号是否正确；2. 税局是否有核定，新注册企业或税费种认定到期也会返回该提示。
Q27. 期限类别[1]期限代码[01]税务机关代码[XXXXXX]配置信息缺失
答：税局提示企业主管税务机关信息有问题或不完整，需要企业和税局联系处理。

二、人员信息登记报送

Q5. 累计减除费用校验不通过：应 ≤ [XXXXX]，实际填写 60000.00
答：一般为任职受雇日期报送和实际不符，税局累计减除费用为 60000 说明这个人去年应该也在这个企业任职。
注意：当前已支持根据往期累计数自动带入 6 万减除费用的备注，用户可以不传。
Q7. 上一属期未按照 6 万扣除累计减除费用
答：因为人员上个月未按照一次性减除 6 万来申报，所以本期不能传按照 6 万减除的备注。
注意：当前已支持根据往期累计数自动带入 6 万减除费用的备注，用户可以不传。
Q17. 本月超过报送次数，不允许再次报送
答：税局对当月人员报送次数有限制，根据观察记录，每月有 150 次限制。
Q20. 人员信息与所得项目不匹配
答：人员报送的任职受雇类型和收入不匹配。对应表详见：个税附录。

三、算税管理

Q3. 发起申报后报错"应扣缴税额不一致，请检查"
答：排查方向：1. 确认传入的应扣缴税额 ykjse 和算税出来的累计应扣缴税额 ljyingkjse 是否一致（所有员工的合计），可通过「申报内置算税结果查询」接口查询；2. 再确认本期收入是否正确，常见不一致是累计专项扣除和专项附加扣除不一致。
Q15. 异步算税 专项附加扣除累计数返回值为 0
答：1. 确认员工是否归属该扣缴义务人且是否传入了累计专附扣数据；2. 确认请求入参 zcgzxjsfcrlj 值是否为 1，1 为不下载专项附加信息以传入的为准。
Q21. 正常工资薪金当前存在单批次算税，请清空后再进行多次批次算税
答：同一所属期不能同时使用多批次算税和单批次算税。

四、申报管理

Q8. 检测到税款所属期为 4 月的申报数据发生了变动，请同步更正 4 月后的申报数据
答：4 月属期做过更正申报，4 月之后的月份要依次按照顺序更正。
Q14. 已请求更正申报接口，提示不能远程补报之前的税款所属期
答：更正申报失败时会恢复之前的申报标记，如果需要再次发起更正申报，需要重新请求申报更正接口。
Q18. 局端接口返回异常: 该笔申报已开票，不允许作废
答：因为已缴款或缴款中，可查看是否发起过扫码缴款或打印缴款凭证。发起过扫码缴款的需要请求「电子税票号码作废」接口。
Q23. 正常工薪、一次性奖金可以分开申报吗
答：不能，综合所得下边的项目要一起发起申报。
Q29. 个税更正申报三种情形（A 新增人员；B 减少人员；C 人员不变仅调整收入）系统是否均支持
答：税局支持的我们都支持：更正本期可以增员；更正往期不能增员；减员和人员不变更都支持。
Q31. 申报作废后再重新申报提示：税款年度内请勿重复申报
答：税局作废有延迟的情况，建议隔天再发起申报。
Q32. 开具失败：本地扣缴端不存在属期的申报记录，无法开具完税证明
答：该纳税人不是在客户端申报的，在网页端申报或者大厅申报的，这种在客户端开不了完税证明。

五、缴款管理

Q10. 三方协议缴款提示未签约，查询能正常返回三方协议号
答：需客户登录电子税局查看三方协议状态，自然人可能会有状态同步慢的情况。
Q16. 作废电子税票号提示：订单作废失败，请检查
答：发起缴款时税局返回异常了，但税局接收到受理订单了，所以作废不了；隔段时间查询缴款状态或者明天再查询试下。
Q22. 缴款书凭证有效期是多长时间
答：征期内，在征期结束前都可以用。征期后一般都是当天，因为出了征期涉及到滞纳金了。
Q30. 缴税款失败，"该笔业务正在办理中，请次日查看缴税结果"
答：这是税局的返回，可以隔一段时间再次发起缴款，或者次日再次发起缴款查询。

六、生产经营所得

Q13. 生产经营B表 —— 该纳税人已申报生产经营B表，不允许继续申报或更正A表
答：一般客户已经做过年度申报，不需要再申报或者调整季度申报数据。
Q19. 生产经营：申报更正状态下不能作废，请先撤销更正
答：生产经营申报是按照投资人申报的，存在部分成功部分失败。如果更正申报后要作废，需要发起撤销更正，将更正失败的投资人状态恢复为"未更正"。
Q24. 企业注册返回的经济类型名称怎么区分是否是个体户，享受减半征收
答：jjlxmc: "私营独资企业" → 个人独资；jjlxmc: "内资个体" → 个体工商户；jjlxmc: "私营合伙企业" → 有限合伙。
Q25. 不支持的征收方式:3 不支持定期定额申报
答：自然人扣缴客户端不支持定期定额的生产经营申报，这个需要在电子税局申报增值税时申报定期定额表。
Q26. 生产经营的个体户减半征收的减免税额怎么计算
答：减免税额 = 应纳税额 - round(应纳税额 × 0.5, 2)
很多客户直接使用 应纳税额×0.5 导致和税局 1 分钱尾差。例如：应纳税额 571.23 → 571.23×0.5=285.615 → 四舍五入 285.62 → 减免税额 = 571.23-285.62 = 285.61
Q33. 经营所得接口设置报税种类需选征收方式，为什么接口还需要传
答：税局接口需要，手工报不需要是因为客户端本地存储了，但税局接口没有，局端接口交互是必需要传的。「获取企业及投资者信息（生产经营）」接口会返回征收方式。

七、其他 / 枚举对照

Q28. 个税减免性质枚举表里"其他非连续劳务报酬"对应哪个所得项目
答：对应的是不适用累计减除的那些所得项目：0401 一般劳务报酬所得、0404 法律援助补贴劳务报酬。
关键业务规则总结：
  1. 6 万减除费用已支持自动带入，用户可不传
  2. 更正本期可增员，更正往期不能增员
  3. 工资薪金和全年一次性奖金不能分开申报，必须一起
  4. 同一所属期不能同时使用单批次和多批次算税
  5. 人员报送每月 150 次限制
  6. 税局作废有延迟，建议隔天再申报
  7. 网页端/大厅申报的无法在客户端开具完税证明
  8. 个体户减半征收：减免税额 = 应纳税额 - round(应纳税额×0.5, 2)，避免直接×0.5 的尾差
  9. 三方协议：自然人状态同步慢，需登录电子税局确认
  10. 生产经营征收方式接口必传，客户端本地已存储但税局接口无
